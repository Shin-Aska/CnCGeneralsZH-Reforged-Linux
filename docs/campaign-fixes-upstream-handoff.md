## Upstream validation plan

No upstream runtime or build validation is represented here. Before proposing candidate ports:

1. Reproduce the relevant campaign symptom on the pinned or newer upstream source with current
   assets; log native scheduled logic rate, current game speed, render cap, client frames and
   scripted completion. Do not reuse fork frame counts or `22/44 Hz` assumptions.
2. For timer/speech changes, add deterministic script-pass tests and campaign traces. Cover 100%,
   125%, 150% and 200% game speed; freeze and resume; equal-value countdowns; a speech condition
   polled before its matching request; and unplayed-name fallback.
3. For camera/animation changes, use a non-recording visible run and a lean trace of logic frame,
   W3D animation sync, camera path phase and present time. Keep normal repeats separate from
   phase-4 pictures. Test turn, zoom, pitch, hard cuts, cancellation, pause, debug/script freeze,
   world freeze, capture/replay/network exclusions, and input handoff.
4. Review original campaign narration on movie, minimum-spec, no-movie and failed-video paths.
   Observe actual audio and wait duration with long/localized voices, mute, skip, focus loss and
   quit. The fork audit covers all 36 selected slots statically and startup only; it is not a
   complete campaign playthrough or an upstream audio validation.
5. Test water only if the missing Clean FFT feature is proposed as a separate port. First reproduce
   a corresponding upstream failure; do not transplant the fork-only helper guard by itself.
